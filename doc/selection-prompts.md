# 選定用プロンプト集

- **バージョン**: 0.1
- **最終更新日**: 2026-04-18
- **用途**: 技術選定・意思決定時に LLM（Claude 等）へ比較案を依頼するためのプロンプトテンプレート集。
- **関連**: [`requirements.md`](./requirements.md)

---

## 使い方

1. 各プロンプトの「前提」欄を自プロジェクトの最新状況に合わせて編集。
2. Claude / ChatGPT 等に投げ、比較表・推奨案・実装ステップを得る。
3. 得られた結論は `requirements.md` §10 または `tech-stack-decisions.md`（将来のADR）に反映。

---

## 1. 認証プロバイダ選定

```
あなたは Remix + Supabase 構成の個人向けWebアプリ（PWA）のアーキテクトです。
以下の前提で、認証プロバイダの選定案を比較してください。

# 前提
- フロントエンド: Remix (React Router v7) + TypeScript
- DB/BaaS: Supabase (Postgres + RLS)
- 想定MAU: MVP 10人 → 1年後 1,000人
- 認証方式: メール/パスワード必須、Google OAuth は歓迎、MFAは将来検討
- コスト要件: MVPは月1,000円以内
- セキュリティ: RLS でユーザー間データ分離を担保したい
- 運用: 1人開発、運用負荷は最小化したい

# 出力形式
1. 候補3〜4社の比較表（実装容易性/コスト/RLS連携/MFA/OAuth/運用負荷）
2. 各候補の推奨シナリオ
3. 第一推奨とその理由
4. 採用時の実装ステップ概要（主要ライブラリ・設定ファイル）
5. 将来 MAU 1万到達時のコスト影響
```

## 2. ホスティング先選定

```
Remix + Supabase 構成の個人開発Webアプリをホスティングする先を選定したい。
以下の前提で比較提案してください。

# 前提
- アプリ: Remix v2 (または React Router v7) の SSR アプリ
- DB: Supabase（Tokyo リージョン）
- 外部API: Anthropic Claude (Haiku 4.5), Google Vision
- 想定規模: MVP MAU 10 → 1年後 1,000 → 2年後 10,000
- PWA対応必須（Service Worker）
- 画像アップロード（レシート、〜5MB）を扱う
- 予算: MVP期は月1,000円以内、本番 10,000円以内を目標

# 観点
- Remixとの相性・公式アダプタ成熟度
- エッジ vs Node ランタイムの制約
- コールドスタート・応答速度
- 日本からのレイテンシ
- 画像アップロード・ストリーミングLLM応答の扱い
- 料金体系（固定・従量・帯域課金）
- CI/CD 統合、プレビュー環境
- 障害時の冗長性

# 出力
1. 候補3〜4の詳細比較表
2. 規模別推奨（MVP / 1,000 MAU / 10,000 MAU）
3. 第一推奨と移行戦略（後から変えやすいか）
```

## 3. デザインシステム選定

```
Remix + Tailwind 構成のPWAアプリ向けに、UIコンポーネント戦略を選定したい。

# 前提
- フレームワーク: Remix + TypeScript
- スタイリング: Tailwind CSS v3 or v4（どちらが推奨かも提案）
- PWA必須（バンドルサイズ重視）
- モバイルファースト、カメラ撮影UIあり
- ダークモード対応
- 日本語UI（フォント・行間考慮）
- アクセシビリティ WCAG 2.1 AA 目標
- 1人開発、デザイナーなし

# 比較観点
- Remix SSR との相性（hydration, FOUC）
- バンドルサイズへの影響
- アクセシビリティ（キーボード操作、ARIA）
- 日本語フォントとの相性
- モバイル特有UI（BottomSheet, カレンダー, カメラ）の提供有無
- 将来のデザイン刷新容易性
- Figma との連携容易性

# 出力
1. shadcn/ui・Mantine・Chakra v3・Panda+ParkUI を中心とした比較
2. 各方針でのテーマカスタム例（色・フォント）
3. 推奨構成 + 追加で入れるべきライブラリ（日付, アイコン, チャート）
4. サンプルコンポーネント実装例（Button, Card）
```

## 4. 決済・サブスク化戦略

```
個人開発の食料管理＆レシピ提案Webアプリで、将来の収益化を見据えた戦略を提案してください。

# 前提
- 開発者: 日本在住個人（副業レベル）
- MVP想定ユーザー: 10人（家族・友人）
- 将来想定: 1,000〜10,000 MAU
- 主要コスト: Claude API, Google Vision API（利用量比例）
- 日本市場向け（インボイス制度、消費税の考慮必要）

# 検討項目
1. 収益化のタイミング（MVP, β, v1.0, 後付け）
2. モデル（寄付 / Freemium / サブスク / 従量 / 買い切り）
3. 決済基盤（Stripe vs Paddle vs LemonSqueezy vs Revenue Cat）の日本個人での使い勝手
4. インボイス制度対応（Merchant of Record 方式のメリット）
5. 無料枠・有料機能の境界設計案（3プラン）
6. 変動コスト（LLM/OCR）を踏まえた損益分岐点試算
7. 後から有料化しやすいDB/コード設計の先行実装

# 出力
- 推奨ロードマップ（フェーズ別）
- 3プラン設計案（Free/Standard/Family）
- MVP で先行実装すべき「後付け容易化」のコード設計メモ
- 日本個人開発者視点の決済基盤推奨理由
```
