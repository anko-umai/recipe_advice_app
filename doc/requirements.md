# 要件仕様書：食料管理＆レシピ提案アプリ

- **ドキュメント種別**: 要件仕様書（Requirements Specification）
- **バージョン**: 0.1（ドラフト）
- **最終更新日**: 2026-04-18
- **対象ブランチ**: `claude/recipe-food-app-requirements-8mhgU`

---

## 1. 概要

### 1.1 目的
家庭内の食料在庫を可視化し、在庫から作れるレシピをAIが提案、調理履歴をカレンダーで管理、調理実行時に在庫を自動減算することで、**フードロス削減**と**献立検討コストの低減**を実現する個人向けWebアプリ。

### 1.2 解決したい課題
- 何を買ったか覚えておらず、同じ食材を重複購入してしまう。
- 食材を使い切れず廃棄してしまう（フードロス）。
- 毎日の献立を考えるのが負担。
- 過去に作った料理・レシピを思い出せない。

### 1.3 主要機能（概要）
| No. | 機能 | 概要 |
|-----|------|------|
| ① | 食料在庫管理 | 手入力 or レシートOCRで在庫を追加・編集・削除。 |
| ② | レシピ提案 | 在庫食材を元にLLMが動的にレシピを生成・提案。 |
| ③ | 調理カレンダー | 作った料理をカレンダーに記録、日付からレシピ再確認。 |
| ④ | 在庫自動減算 | 調理完了時に使用食材分の在庫を自動減算。 |

## 2. 対象ユーザー・利用形態

### 2.1 ユーザー像
- 自炊をする単身〜小家族の個人。
- スマホで買い物帰りに在庫登録したい。
- PCでゆっくり献立を検討したい。

### 2.2 利用形態
- **1アカウント = 1冷蔵庫（個人単位）**。
- 家族・世帯での共有機能は v1.0 スコープ外（将来拡張）。

## 3. プラットフォーム・技術方針

### 3.1 対象プラットフォーム
- **Webアプリ ＋ PWA**
  - レスポンシブ対応（スマホ・タブレット・PC）。
  - PWA化によりホーム画面追加・オフライン閲覧（在庫/履歴のキャッシュ表示）を実現。
  - PWA経由でスマホカメラを呼び出してレシート撮影。

### 3.2 採用技術スタック（暫定確定）

| レイヤー | 採用技術 | 備考 |
|----------|---------|------|
| フロントエンド | **Remix (React Router v7) + TypeScript + Tailwind CSS** | SSR・ネストルーティング活用 |
| UI コンポーネント | **Tailwind CSS + shadcn/ui** | Radix UI ベース、プロジェクト内にソース配置 |
| PWA | Workbox（Remix用アダプタ併用） | オフライン対応・ホーム画面追加 |
| バックエンド | Remix Loader/Action（同一プロジェクト） | 必要に応じてサーバー関数追加 |
| DB | **PostgreSQL (Supabase)** | Tokyoリージョン、RLS利用 |
| 認証 | **Supabase Auth** | メール/パスワード + Google OAuth、RLSと一体運用 |
| OCR | **Google Cloud Vision API**（Document Text Detection） | 月1,000件まで無料枠 |
| LLM | **Anthropic Claude API（Haiku 4.5 主軸）** | 必要時のみ Sonnet 4.6 にエスカレート |
| ストレージ | Supabase Storage | レシート画像。保持期限 90日（デフォルト） |
| ホスティング | **Cloudflare Pages + Workers** | エッジ実行、帯域無料、MVPコスト最小化 |
| 決済 | なし（MVP無料） | 課金導線のみDB/コード側で先行設計 |

> すべてアダプタ／抽象化層を挟み、将来の差し替え容易性を確保（NFR-M-01, NFR-M-02）。

## 4. 機能要件

### 4.1 ユーザー・認証

| ID | 要件 |
|----|------|
| FR-A-01 | メールアドレス＋パスワードで新規登録・ログインできる。 |
| FR-A-02 | ログアウトできる。 |
| FR-A-03 | パスワードリセット（メール経由）ができる。 |
| FR-A-04 | 退会（アカウント・関連データ削除）ができる。 |
| FR-A-05 | 認証済みユーザーのみが在庫・レシピ・カレンダーにアクセスできる。 |

### 4.2 食料在庫管理（機能①）

#### 4.2.1 手入力
| ID | 要件 |
|----|------|
| FR-I-01 | 食材名・数量・単位・購入日・賞味期限・保存場所（冷蔵/冷凍/常温）を登録できる。 |
| FR-I-02 | 登録済み食材を編集・削除できる。 |
| FR-I-03 | 在庫一覧をカテゴリ（野菜・肉・魚・乳製品等）ごとに絞り込み・ソートできる。 |
| FR-I-04 | 賞味期限が近い食材をハイライト表示（3日以内：黄、当日以前：赤）できる。 |
| FR-I-05 | 食材名はマスタデータ（正規化された食材リスト）から補完サジェストされる。 |

#### 4.2.2 レシート読み取り
| ID | 要件 |
|----|------|
| FR-R-01 | スマホカメラ or 画像アップロードでレシート画像を取り込める。 |
| FR-R-02 | Google Cloud Vision API で画像をOCRし、テキストを抽出する。 |
| FR-R-03 | 抽出結果を LLM で構造化（商品名・数量・単価・合計）し、食材候補に変換する。 |
| FR-R-04 | 店舗独自の略称（例: 「ﾄﾏﾄ」「GFﾆﾝｼﾞﾝ」）を食材マスタにマッピングする。 |
| FR-R-05 | 抽出結果はユーザーが確認・修正してから在庫登録する（誤認識対策）。 |
| FR-R-06 | レシート画像は登録後、任意で保持/破棄を選択可能（プライバシー配慮）。 |
| FR-R-07 | 食品以外の行（日用品・割引・合計行）は自動除外する。 |

### 4.3 レシピ提案（機能②）

| ID | 要件 |
|----|------|
| FR-P-01 | 現在の在庫一覧から、Claude APIでレシピを3〜5件提案する。 |
| FR-P-02 | 提案時、優先使用食材（賞味期限が近い順）を考慮する。 |
| FR-P-03 | ユーザーは絞り込み条件（和/洋/中、所要時間、品数、調理難度、アレルギー除外）を指定できる。 |
| FR-P-04 | 各レシピには「材料（在庫で賄える分／不足分）」「手順」「所要時間」「想定カロリー」を表示する。 |
| FR-P-05 | 生成レシピはお気に入り登録でき、後から一覧参照できる。 |
| FR-P-06 | LLM生成結果はキャッシュし、同条件の再リクエストは再利用（コスト抑制）。 |
| FR-P-07 | 不足食材は「買い物リスト」として出力できる。 |

### 4.4 調理カレンダー（機能③）

| ID | 要件 |
|----|------|
| FR-C-01 | 調理した料理を日付（＋朝/昼/夜区分）に紐づけて記録できる。 |
| FR-C-02 | 月次カレンダー表示で、過去の調理履歴を俯瞰できる。 |
| FR-C-03 | カレンダーの各エントリから、当時のレシピ詳細を再表示できる。 |
| FR-C-04 | レシピには「星評価（1〜5）」「感想メモ」を後から追記できる。 |
| FR-C-05 | 月次で「作った料理数」「カテゴリ別割合」等の簡易統計を表示する。 |
| FR-C-06 | 日付検索、料理名での全文検索ができる。 |

### 4.5 在庫自動減算（機能④）

| ID | 要件 |
|----|------|
| FR-D-01 | 「調理済み」ボタン押下時に、レシピ材料分を在庫から減算する。 |
| FR-D-02 | 減算前にユーザーは数量を調整できる（実際に使った量が異なる場合）。 |
| FR-D-03 | 在庫不足の材料は警告表示しつつ、ユーザー判断で強制実行可能。 |
| FR-D-04 | 減算履歴を監査ログとして保持し、誤操作時にロールバック可能（直近10件）。 |
| FR-D-05 | 数量が0になった食材は自動的に在庫一覧から非表示（論理削除）。 |

|----|------|
| NFR-P-01 | 在庫一覧表示：P95 1.5秒以内。 |

| ID | 要件 |
|----|------|

| ID | 要件 |
|----|------|
| NFR-S-01 | 通信は全てHTTPS。 |

## 6. データモデル概要

```
User (1) ── (N) Ingredient            // 在庫食材
User (1) ── (N) Receipt               // レシート画像・OCR結果
User (1) ── (N) Recipe                // 保存/お気に入りレシピ
User (1) ── (N) CookingLog            // 調理履歴
CookingLog (N) ── (1) Recipe
CookingLog (N) ── (N) Ingredient      // 使用食材ログ
Ingredient (N) ── (1) IngredientMaster // 食材マスタ（正規化辞書）
```

### 6.1 主要エンティティ

#### User
- id, email, display_name, created_at

#### Ingredient（在庫食材）
- id, user_id, master_id, name, quantity, unit, storage_type, purchased_at, expires_at, note, deleted_at

#### IngredientMaster（食材マスタ）
- id, canonical_name, category, default_unit, aliases[]

#### Receipt
- id, user_id, image_url, ocr_raw_text, parsed_items(JSON), status, created_at

#### Recipe
- id, user_id, title, cuisine, duration_min, difficulty, ingredients(JSON), steps(JSON), calories, source(ai/user/external), is_favorite, created_at

#### CookingLog
- id, user_id, recipe_id, cooked_at, meal_type(breakfast/lunch/dinner/other), rating, memo

#### InventoryAudit（減算ログ）
- id, user_id, cooking_log_id, ingredient_id, delta, before_qty, after_qty, created_at

## 9. 前提・制約事項

- 初期リリースは **日本語・日本国内向け** のみ。
- レシート対応は日本の主要スーパーのフォーマットを優先。
- LLM生成レシピは参考情報であり、アレルギー・食中毒に関する最終判断はユーザー責任。
- 外部API（Claude / Google Vision）の利用規約・料金体系に準拠。
